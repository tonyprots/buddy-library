# Подключение Бадди: инструкция агенту

Задача — встроить героя в существующую HTML-презентацию. Начните с одного
готового файла, сохраняйте оформление, содержание и навигацию владельца.
Это руководство для интеграции, не требование менять правила проекта.

## Сначала осмотрите презентацию

Найдите сцену, конечные слайды, способ скрытия неактивных слайдов и активный
класс. Проверьте логический размер: Бадди рассчитан на 1280×720, допускает
равномерный CSS scale всей сцены. Для другого размера предложите адаптацию;
не меняйте геометрию всей презентации молча.

Не переписывайте клавиатурные обработчики, роутер, переходы или CSS слайдов.
Не копируйте в проект внутренности runtime и vendor. Не добавляйте npm,
сервер, React или другой сборщик ради одного скрипта.

## Обычный HTML: основной путь

Скопируйте `dist/buddy.js` (в web-архиве — `buddy.js`) рядом с презентацией,
сохраните LICENSE и THIRD_PARTY_NOTICES.md. Подключите:

```html
<script defer src="./buddy.js" data-stage="#stage"></script>
```

Дефолт: прямые дочерние `.slide` и активный класс `on`.
Если имена отличаются, используйте адаптер разметки:

```html
<script defer src="./buddy.js" data-stage="#deck"
  data-slide-selector=".pages > article" data-active-class="is-active"></script>
```

Селектор ищет внутри сцены и должен вернуть только конечные слайды
в порядке показа. Навигация страницы сама меняет активный класс и видимость;
Бадди следит за изменением. Не добавляйте ему собственную навигацию.

Скрипт без `data-stage` только создаёт глобальный `Buddy`.
Тогда после его загрузки и монтирования сцены вызовите
`await Buddy.createBuddy({ stage, slideSelector, activeClass })`.
Не используйте автоподключение и ручной вызов одновременно.
Для ESM и сборщиков — [справочник](api.md#es-модули-и-сборщики).

Знаки Яндекс 360 — отдельный необязательный пример из исходников.
Не копируйте buddy-y360.js и не включайте y360 без запроса владельца.
Если нужны знаки, передавайте `logos` явно по справочнику; одного
`presets: { y360: true }` начиная с 0.8.3 недостаточно для изображений.

## Сохраните активные настройки

`createBuddy({ stage })` уже включает show/curious, самостоятельную жизнь,
реакции и способности. К концу деки герой разгоняется; один слайд получает
средний уровень. Не добавляйте `autonomous: false`, `reactions: false`,
`mode: 'manual'` или `profile: 'calm'` «для надёжности».
Не запускайте все 93 приёма подряд: пространство и контекст ограничивают выбор.

Не переопределяйте системное reduced motion. Предоставьте доступную кнопку
паузы через `pause()` / `resume()`; никакого обязательного меню настройки.
В SVG без WebGL сложный реквизит упрощается — это штатный резервный режим.

## Если у презентации есть бренд

Определяйте бренд при интеграции, не во время показа. Ищите главный знак
в обложке, подписи или шапке; продукты — в явно подписанном наборе сервисов;
акцент — в переменных CSS и повторяющихся фирменных элементах. Случайная
картинка, логотип клиента или единственная цветная диаграмма не доказывают бренд.
Если выбор неуверенный, оставьте обычного героя; не выдумывайте изображения.

Соберите `{ logo, products, accent }` из ресурсов этой презентации.
`products` может быть пустым. Сохраните изображения рядом с HTML или встроите
data-URI; для inline SVG сохраните viewBox, defs и используемые стили, затем
закодируйте полный SVG. Не переносите чужие знаки в репозиторий библиотеки.
Веб-поиск — только запасной путь и только с согласия владельца презентации.

Для страницы без сборщика добавьте JSON-блок и `data-brand`:

```html
<script type="application/json" id="deck-brand">
{"logo":"./assets/logo.svg","products":["./assets/product.svg"],"accent":"#267052"}
</script>
<script defer src="./buddy.js" data-stage="#stage" data-brand="#deck-brand"></script>
```

Для существующего JS используйте `createBuddy({ stage, brand })`.
Фирменные номера включаются сами. Не добавляйте флаг y360 к чужому бренду.
Если конкретный номер требует другого изображения, задайте необязательную
роль по [справочнику](api.md#бренд-презентации). Сохраните системный reduced motion.

Проверьте, что знак загрузился, цвет худи относится к бренду, продукты появились
на орбите `shield`, а в консоли нет ошибок загрузки. Одного показа достаточно:
полный тестовый набор библиотеки пользователю не нужен.

## Точечные настройки

- Оставьте у нижнего края место для героя. Он находит опоры автоматически;
  панель управления лучше держать за пределами сцены.
- После изменения вёрстки внутри слайда вызовите `buddy.rescan()`, не каждый кадр.
- При SPA-размонтировании — `buddy.destroy()`. При изменении набора слайдов
  создайте экземпляр заново. До окончания async-запуска используйте `signal`
  из AbortController, чтобы отменить запуск.
- Для явного номера используйте `perform()` / `story()`, учитывайте
  `can()` и результат `finished`; не обращайтесь к `experimental`.
- Сложные графики и связи размечайте по [руководству контекста](slide-context.md).
  Тексты и числа не выдумывайте; всё берётся со слайда.

## reveal.js и другие движки

Настройте сцену 1280×720 в самом движке, выберите только конечные слайды и
его активный класс (например, `present`). Создавайте Бадди после готовности
движка. При анимированном переходе пересчитайте геометрию после его окончания
(в reveal.js — `slidetransitionend`), а после смены фрагмента — по его событию.
Не меняйте обработчик перехода и не подключайте `attachDeckEffects`:
этот необязательный модуль рассчитан на `.slide` / `on`.
Универсальная совместимость с плагинами и вложенной навигацией не гарантируется.

## Достаточная проверка

Откройте итоговый HTML тем же способом, что владелец. Убедитесь, что герой
появился и двигается без включения опций, навигация и ссылки работают,
при переходе меняются контекст и активный слайд, пауза работает, ошибок
загрузки нет. Посмотрите первый и последний слайды и узкое окно.
С reduced motion герой должен быть неподвижен.

Полный набор тестов библиотеки, браузерный стенд и установка devDependencies
для такой интеграции не нужны. Сообщите владельцу, какой HTML изменён и
где лежит buddy.js; перечислите только реальные ограничения.
